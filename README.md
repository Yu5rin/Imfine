# I'm fine

モニターのスリープと Microsoft Teams の「退席中」表示を防ぐ Windows 用常駐ツールです。

## 主な機能

- ワンクリックの ON/OFF スイッチ（キーボードでも Tab で選んで Space / Enter で切り替え）
- ON の間はモニターのスリープを抑止し、30秒ごとにアクティブ状態を維持
  （F15キーの押下イベントとマウスの1px移動を、その時点でフォアグラウンドに
  ある任意のアプリへ送信する方式です。ゲームやリモートデスクトップ、
  F15キーにショートカットを割り当てているアプリでは意図しない副作用が
  起きる可能性があります。また、キー入力・マウス操作のシミュレーションを
  行うため、企業環境ではこの挙動自体が監視・検知の対象になり得る点にも
  注意してください）
- 決まった時刻に自動で OFF（ON の間に時刻を変えてもすぐ反映）
- タスクトレイ常駐（起動している間はアイコンを常に表示。ON は緑のチェック、
  OFF は灰色の一時停止の絵）
- 二重に起動したときは、動いている I'm fine のウィンドウを前に出す
- テーマ: Windows に合わせる / ライト / ダーク
- 起動時に自動で ON、起動時にトレイへ格納、Windows の起動時に起動
- ウィンドウ位置と設定の自動保存
- 自動更新（設定で有効/無効を切り替え可能。有効時は起動したときと、起動中は
  6時間ごとに新しい版がないか確認し、あればダウンロード・SHA256検証・
  自己置き換え・再起動まで自動で行う。検証に失敗した場合は何もせず現在の
  版のまま動作を続ける）
  - この SHA256 検証は、ダウンロードした exe と GitHub API が返す期待値
    (同じレスポンスに含まれる digest) を突き合わせるものです。つまり
    **通信中の破損や取りこぼしを検知するためのものであり**、GitHub の
    アカウントが乗っ取られてリリース自体が改ざんされた場合の検知には
    なりません（exe とハッシュを同時に差し替えられてしまうため）。
  - 更新確認先は `api.github.com` に固定されており、設定ファイルを
    直接編集しても他のホストへ変更することはできません
    （更新の仕組みが任意のサーバーへの自己置き換えに悪用されるのを
    防ぐための制限です）。

## 動作環境

- Windows 10 / 11（64ビット）
- タイトルバーの色をテーマに合わせる表示は Windows 11 22H2（ビルド 22621）以降のみ。
  それより前の環境では OS 標準のタイトルバーのまま動作します
- 自動更新を使う場合は `api.github.com` と GitHub のダウンロード用ホストへ
  接続できること

## インストールと更新

### インストール

Releases ページから最新の ImFine.exe をダウンロードして実行するだけです。
インストール不要のポータブル形式です。

https://github.com/Yu5rin/Imfine/releases

ImFine.exe は、自分で書き込みできるフォルダ（例: ドキュメントやデスクトップの下）に
置いてください。自動更新は ImFine.exe のあるフォルダで exe を入れ替えるため、
書き込みできない場所（`C:\Program Files` など）では更新が行われません。

### 更新

- **自動更新（既定で有効）**: 起動したとき、また起動中も6時間ごとに
  新しい版がないか確認し、あればダウンロード・SHA256検証・入れ替え・
  再起動まで自動で行います。ON のまま更新された場合は、再起動後も ON に戻ります
  （経過時間も引き継ぎます。ただし再起動の間に停止時刻を過ぎていれば OFF のままです）。
  タスクトレイに格納していた場合も、再起動後はウィンドウを出さずトレイに格納されます。
  設定ウィンドウや確認のダイアログを開いている間は、閉じるまで更新を待ちます
- **手動で確認する**: 設定ウィンドウの「今すぐ確認」、またはタスクトレイの
  右クリックメニューの「更新を確認」から、自動更新の設定に関係なく確認できます。
  結果は「今すぐ確認」の横（トレイから確認したときは通知）に出ます
- **自分で入れ替える**: 自動更新を無効にしている場合や、自動で更新できない
  場合は、Releases ページから最新の ImFine.exe をダウンロードし、今ある ImFine.exe と
  置き換えてください。設定は別の場所（下の「設定ファイル」）に保存されているため、
  そのまま引き継がれます

更新の記録は `data` フォルダ（下の「設定ファイル」）の `update.log` に残ります。設定ウィンドウの
「更新の記録を開く」から開けます。更新がうまくいかない場合は、このファイルを見ると原因が分かります。

## 使い方

1. ImFine.exe を起動する
2. 一番上のスイッチをクリックして ON にする。もう一度クリックすると OFF
3. 最小化、またはウィンドウの × ボタンでタスクトレイに格納される（設定で変更可能）。
   終了はタスクトレイの右クリックメニューの「終了」から（ON のときだけ確認が出ます）

メイン画面には、状態（ON と経過時間、または OFF）と、その下に
「17:00 に自動で OFF にします」（翌日なら「明日 17:00 に…」）のような補足が出ます。

### 停止時刻

「決まった時刻に自動で OFF にする」にチェックを入れて時刻を設定すると、その時刻に自動で
OFF になり、通知が出ます。指定時刻が現在より前の場合は翌日のその時刻に OFF にします。
時刻は数字で打ち込むか、矢印で選びます。打ち込んだ値は、Enter を押すか別の場所を
選んだときに確定します（範囲外の値は 0〜23 時・0〜59 分に収めます）。

### タスクトレイ

アイコンは起動している間いつも表示されます。

- 左クリック: ON/OFF の切り替え
- 左ダブルクリック: ウィンドウを開く
- マウスを重ねる: 今の状態（例:「I'm fine - ON（17:00 に自動で OFF）」）
- 右クリック: メニュー
  - **ON** … チェックが今の状態。選ぶと切り替え
  - **17:00 に自動で OFF** … 停止時刻を使っているときだけ表示（選べません）
  - **ウィンドウを開く** / **設定…**
  - **更新を確認** / **データフォルダを開く**
  - **I'm fine vX.Y.Z** … 今の版（選べません）
  - **終了**

ON/OFF を切り替えたときの通知は、設定で出すようにできます（既定は出さない）。
自動で OFF にしたときと、更新のときは必ず通知が出ます。

### 設定

メイン画面右下の「設定」ボタン、またはトレイのメニューの「設定…」から開きます。
Esc キーか「閉じる」で閉じます。

- **起動**
  - Windows の起動時に I'm fine を起動する（exe を移動した場合は、次の起動時に
    今の場所で登録し直します）
  - I'm fine の起動時に自動で ON にする
  - 起動時はウィンドウを出さずタスクトレイに格納する
- **タスクトレイ**
  - 最小化したらタスクトレイに格納する（既定: オン）
  - 閉じる（×）でタスクトレイに格納する（既定: オン。オフにすると × で終了します）
  - ON/OFF を切り替えたとき通知する（既定: オフ）
- **表示**
  - テーマ: Windows に合わせる（既定）/ ライト / ダーク
- **更新**
  - 自動で更新する（既定: オン）
  - 「今すぐ確認」ボタン
- 「データフォルダを開く」「更新の記録を開く」ボタン

## 開発

Python 3.11 + tkinter 製。ビルドには PyInstaller を使用します。

```
pip install -r requirements.txt
python icon_gen.py
pyinstaller ImFine.spec
```

テストは `python -m unittest discover -s tests` で回します（標準ライブラリだけで動き、
tkinter や Pillow が無くても実行できます）。リリースのワークフローも、ビルドの前に
同じテストを実行します。exe に埋め込むバージョン情報は、ビルドのたびに
`ImFine.spec` が `ui.py` の `VERSION` から `version_info.txt` を作って使います。

GitHub Actions の Build and Release ワークフローを手動実行すると、
ui.py のバージョンを読み取って自動でタグ付け・リリースされます。

### リリース手順

1. リリース前に `CHANGELOG.md` へ `## v<バージョン>` の節を追記する（見出しはリリースタグ名と完全一致させること）
2. `ui.py` の `VERSION` をその版に上げる（画面に出るバージョンはここから取る。タグと一致しないとビルド前にワークフローが失敗する）
3. ワークフローを実行する（該当節が無いとビルド前にワークフローが失敗する）
4. ワークフローが `CHANGELOG.md` の該当節を自動的に抜き出し、GitHub リリースのリリースノートとして反映する

リリースの本文は「## 変更点」（`CHANGELOG.md` の該当節）と「## ダウンロード」
（ファイル・サイズ・SHA256 の表）の2節と、この README への案内1行だけで作られます。
インストールや更新の方法、機能の説明などは README に書き、リリースには書きません。
`CHANGELOG.md` の節の中では、見出しは `###` 以下を使ってください。

## 設定ファイル

設定（settings.json）、更新の記録（update.log）、想定外のエラーの記録（app.log）は、
ImFine.exe と同じフォルダの `data` フォルダに保存されます。

- **PC を引っ越すとき**: ImFine.exe と `data` フォルダをまとめて新しい PC にコピーしてください
- **書き込めない場所に置いたとき**: Program Files 配下など `data` フォルダを作れない場所では、
  `%APPDATA%\ImFine` に保存されます
- **以前の設定の引き継ぎ**: `data` フォルダに settings.json がないときだけ、
  `%APPDATA%\ImFine`、なければ旧バージョン（Mouser）の `%APPDATA%\Mouser` の設定を
  初回起動時にコピーして引き継ぎます。元のファイルは削除しません
- ソースから実行した場合は、リポジトリ直下の `data` フォルダに保存されます
